## Context

You are working on Pocket Quartermaster. Follow `AGENTS.md` in full (Expo docs over memory: read the versioned docs for the audio library before writing any audio code; `npx expo install` for dependencies; the emoji-in-Text rule; saves must survive; never run the full `npm run sim`).

**What this is for.** Sound that confirms what the player did or earned, in the game's wood, brass and parchment character. Most people play a walking game muted, so sound is a bonus: nothing may depend on hearing it, and haptics already carry the same moments.

**Where sounds come from.**
- **Generated by a script** in this repo: interface and reward sounds, in a soft retro style. Claude can't produce audio directly, but a script can synthesise these from tones and noise, the way `scripts/generate-foliage-sprites.py` generates placeholder art.
- **Recorded, sourced later by me**: sounds that must sound real (hammer on anvil, chopping, rustling, bubbling, ambience). Until I supply them, the script generates a stand-in for each, so every moment has a sound from day one.
- **Every sound is a file with a fixed name.** Replacing a generated sound with a recorded one is dropping a file with the same name into the folder and rebuilding. No code change.

**Rules.**
- **Never interrupt the player's own audio.** Music and podcasts keep playing; game sounds mix on top. No sound in the background, none from Pocket mode, none from notifications beyond what the system plays.
- **Respect the phone.** The silent switch and the media volume apply. The app never changes system volume.
- **Short and quiet.** Interface sounds under 300 ms, reward sounds under 1.2 s, nothing over 2 s except ambience. Levels are normalised so nothing is startling; interface sounds sit well below reward sounds.
- **Never late, never stacked.** A sound that can't start within about 50 ms of its moment is dropped. The same sound doesn't retrigger within 80 ms, and at most four play at once; extra ones are dropped, never queued.
- **Cheap.** Sounds are small files (mono, 16-bit, 22.05 kHz is enough for these), the whole set under 1.5 MB. The few interface sounds are loaded at start; the rest on first use. No effect on the first-open budgets in `src/perf/`.
- **One door.** Components keep calling `feel('moment')`. Nothing outside `src/services/feel.ts` and the audio service touches the audio library.

**How to work.** After each step: `npm run test:changed`, then `npm test`, `npm run typecheck` and `npx expo lint`; a short summary; stop for review. Texts in English and French. Document the rules as built in `doc/design/ui/sound.md`. A new native library means a native rebuild: tell me when I need to run `npm run android:fresh`.

## Step 2 – The generator

1. `scripts/generate-sounds.py`, in the same spirit and language as the foliage script: standard library only (no audio packages), deterministic (a fixed seed, so the same script gives byte-identical files), one function per sound, writing WAV files to `assets/sounds/`. A table at the top lists every sound: name, length, peak level and a one-line description.
2. Building blocks to write once and reuse: sine, triangle and square tones, filtered noise, an attack-decay envelope, pitch slides, a short echo, mixing and normalising.
3. `npm run sounds` runs it. The generated files are committed, as the foliage sprites are, so a build doesn't need Python.
4. A test checks every file in the table exists, is mono, is within its stated length and under the size budget, and that the set stays under 1.5 MB.

## Step 3 – Interface and reward sounds (generated for good)

Generate and wire these. Aim for soft, woody and warm over bright and electronic: low-passed, short decays, no harsh square waves.

| Moment | Sound |
| --- | --- |
| Button press | A soft wooden tick |
| Toggle on / off | Two ticks, rising / falling |
| Tab change | A light tap, slightly higher than a press |
| Sheet opens / closes | A short paper whoosh, up / down |
| Dialog confirm / cancel | A firm knock / a soft double tap |
| Error or can't afford | A low, dull thud |
| Gold gained | Two or three coin clinks; more coins for larger sums, in three sizes |
| Count-up ticking | A very quiet tick, used sparingly: at most six per count |
| Loot tile appears | A small pop, pitched up a step per tile |
| Rare find revealed | A chime per rarity: Uncommon two notes, Rare three, Legendary a short rising arpeggio with an echo |
| "New" find | A sparkle on top of the tile's sound |
| Level up | A rising three-note flourish |
| Quest claimed | A stamp thud, then a short chime |
| Expedition won / flawless / retreat / lost | A short fanfare / a longer one / a neutral two-note fall / a low drum |
| Tier boss beaten | The longest piece, up to 2 s: a fanfare with a drum |
| New title or named gear | A soft bell |
| Notification inside the app (a group is back) | A small horn call, two notes |

Give repeated sounds variety without more files: `feel` shifts the pitch a little at random on presses, pops and coins (within about ±4%), if the audio library can do that cheaply; if it can't, generate three variants of those and rotate.
